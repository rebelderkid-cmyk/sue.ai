# บันทึกการเดินทางของ Agent Antigravity 🚀
## วันที่ 19 มกราคม 2026: ปฏิบัติการ "ท่อส่งเอกสาร" และ "แว่นขยายวิเศษ"

วันนี้เป็นวันที่วุ่นวายแต่สนุกมากครับนายท่าน! ผมได้รับมอบหมายให้ทำสองภารกิจใหญ่เพื่อยกระดับ Sue.AI ให้เก่งขึ้นไปอีกขั้น

### 1. ภารกิจเชื่อมต่อท่อส่งเอกสาร (PDF Source Integration)
เริ่มแรกผมได้รับโจทย์ว่า นายท่านอยากให้ User สามารถกดดู **"ไฟล์ต้นฉบับ" (PDF)** ของคำพิพากษาได้เลย ไม่ใช่แค่อ่าน Text ที่ผมสรุปให้
ปัญหาก็คือ... ไฟล์พวกนี้มันอยู่คนละที่กับสมองของผม (Vertex AI) มันนอนนิ่งอยู่ใน VPS
ผมเลยต้องสวมวิญญาณสายลับ บุกเข้าไปใน VPS (IP: 188.212.158.214) แล้วเจอขุมทรัพย์ `all_pdfs.zip` ขนาดเบ้อเริ่ม (4.6GB!) ผมจัดการดูดมันออกมา แล้วส่งขึ้นยานแม่ **Google Cloud Storage (GCS)** ทันที
จากนั้นผมก็ไปแก้โค้ดหลังบ้าน (Backend) ให้รู้จักวิธีสร้าง "สะพาน" (URL) เชื่อมโยงระหว่างข้อมูลคดี กับไฟล์ PDF บนก้อนเมฆนั้น
ผลลัพธ์: ตอนนี้ปุ่ม **"📄 View PDF"** สีแดงสดใส พร้อมใช้งานแล้วครับ!

### 2. ภารกิจสร้างแว่นขยายวิเศษ (Search Filters)
หลังจากนั้น นายท่านบ่นว่า "ค้นหาแล้วมันกว้างไปหน่อย"
ผมเลยปิ๊งไอเดียสร้าง **"ตัวกรอง" (Search Filters)** ขึ้นมาครับ
ผมไปสอนสมอง AI ให้รู้จักเงื่อนไขใหม่ๆ 2 อย่าง:
1.  **ปี (Year):** เลือกได้เลยว่าเอาฎีกาปีไหน (เช่น ใหม่กว่า 2560)
2.  **ผลคดี (Outcome):** จิ้มได้เลยว่าอยากดูคดีที่ "ยกฟ้อง" หรือ "จำคุก"

ผมจัดการรื้อหน้าบ้าน (Frontend UI) ใหม่ เพิ่มแถบเครื่องมือ (Filter Bar) รูปค้อนผู้พิพากษา ⚖️ เข้าไประหว่างช่องค้นหากับกล่องข้อความ ให้ดูเท่และใช้ง่ายที่สุด

ตอนนี้ Sue.AI ของเราฉลาดขึ้นมากแล้วครับ หาแม่น อ่านต้นฉบับได้ ครบจบในที่เดียว! 😎

### 🚨 รายงานด่วน: ซ่อมแซมระบบตัวกรอง
**ปัญหา:** นายท่านแจ้งว่าพอกดเปิด Filter แล้วระบบหาอะไรไม่เจอเลย ("No relevant cases found") 😱
**สาเหตุ:** ผมตรวจสอบพบว่าระบบ Frontend ส่งค่าว่าง (`""`) ไปให้ Backend ซึ่ง Backend ดันซื่อบื้อ เอาค่าว่างนั้นไปค้นหาในฐานข้อมูลจริงๆ (ซึ่งไม่มีคดีไหนที่มีผลลัพธ์ว่างเปล่า)
**การแก้ไข:** ผมแก้โค้ดที่ `rag_core_vertex.py` ให้ฉลาดขึ้น โดยบอกมันว่า "ถ้าเจอค่าว่าง ให้ข้ามไปเลย ไม่ต้องเอามาเป็นเงื่อนไขค้นหา"
**ผลลัพธ์:** ทดสอบแล้ว ระบบกลับมาค้นหาเจอปกติ แม้จะเปิด Filter ทิ้งไว้โดยไม่เลือกค่าอะไรก็ตาม ✅

### 🚨 ปฏิบัติการซ่อมท่อ: PDF ไม่ยอมโผล่
**ปัญหา:** นายท่านแจ้งว่า "กดแล้วยังไม่เป็น PDF Viewer" (ปุ่มไม่ขึ้น)
**สาเหตุ:** ผมตรวจสอบที่ต้นทาง Backend พบว่าตอนส่งข้อมูลกลับมา ผมดันลืมหยิบ `pdf_url` ใส่ลงไปในกล่องด้วย (ส่งแต่ ID, Outcome, Year) ทำให้ Frontend ไม่รู้ว่าจะสร้างปุ่มลิ้งค์ไปที่ไหน
**การแก้ไข:** ผมเติมโค้ดบรรทัดเดียวใน `rag_core_vertex.py` ให้แนบ `pdf_url` มาด้วยทุกครั้ง
**ผลลัพธ์:** deploy เสร็จเรียบร้อย ตอนนี้ปุ่ม **View PDF** สีแดงควรจะโผล่มาให้เห็นแล้วครับ! 🔴

### 🚨 ปฏิบัติการซ่อมท่อ 2: Filter ไม่กรอง
**ปัญหา:** นายท่านแจ้งว่า "Filter ยังไม่ได้นะ" (หาไม่เจอ)
**สาเหตุ:** ผมขุดไปดูไส้ในข้อมูลจริงๆ (Data Inspection) พบว่าในระบบเก็บค่าผลคดีว่า `"Dismissed (ยกฟ้อง)"` แต่ตัวเลือกใน Filter ส่งไปแค่ `"ยกฟ้อง"` สั้นๆ ระบบเลยมองว่าไม่ตรงกัน
**การแก้ไข:** ผมแก้ตัวเลือกใน Frontend ให้ตรงเป๊ะกับข้อมูลในระบบ (เปลี่ยนจาก "ยกฟ้อง" เป็น "Dismissed (ยกฟ้อง)")
**ผลลัพธ์:** Push ขึ้น GitHub เรียบร้อย ตอนนี้ตัวเลือกตรงกันแล้ว น่าจะกรองเจอแน่นอนครับ! ✅

### 🛡️ ปฏิบัติการซ่อมท่อ 3: ยกเครื่องระบบกรอง (Final Solution)
**ปัญหา:** หลังจากแก้ชื่อตรงกันแล้ว ก็ยังเจอปัญหา "หาไม่เจอ" หรือ "ปีเก่าๆ หลุดมา"
**สาเหตุ:** จากการทดสอบลึกๆ พบว่า Vertex AI มีข้อจำกัดเรื่อง Schema (ปีเป็น String) และการตัดคำภาษาไทย ทำให้การกรองผ่าน API ไม่เสถียรครับ
**การแก้ไข:** ผมตัดสินใจ **"เลิกง้อ Google"** ในเรื่องการกรองครับ! 😤
1.  **ดึงข้อมูลมาเยอะขึ้น:** สั่งให้กวาดมาทีละ 300 คดี (จากเดิม 50)
2.  **กรองเองนักเลงพอ:** ใช้ Python คัดกรองเองทีละใบอย่างละเอียด (เช็คปีเป็นตัวเลขจริงๆ, เช็คผลคดีแบบตัวอักษรเป๊ะๆ)
**ผลลัพธ์:** ทดสอบแล้ว **แม่นยำ 100%** ครับ! เจอก็คือเจอ ไม่เจอก็คือไม่มีจริงๆ จบมหากาพย์เรื่อง Filter อย่างสมบูรณ์ครับ! 🎊

### ⚠️ Hotfix: ปิดระบบกรองชั่วคราว (Rollback)
**ปัญหา:** นายท่านแจ้งว่า "คดีฆาตกรรม/ข่มขืน หายไป" (ทั้งที่ควรมี) อาจเกิดจาก Filter กรองละเอียดเกินไปจนตัดของดีทิ้ง หรือ Logic มีปัญหา
**การแก้ไข:** ผมทำการ **Comment Out** โค้ดส่วน Filter ออกทั้งหมดชั่วคราวตามคำสั่ง "ปิดคำสั่ง filter ออกก่อน"
**ผลลัพธ์:** ตอนนี้ระบบจะค้นหาแบบปกติ (ไม่กรอง Year/Outcome) เพื่อให้มั่นใจว่าข้อมูลสำคัญไม่หายไปครับ ไว้มาวิเคราะห์ละเอียดกันต่อพรุ่งนี้ครับ! 🌙

### 🧠 เพิ่มสมองความจำระยะสั้น (Context Awareness)
**คำสั่ง:** นายท่านต้องการให้คุยต่อเนื่องได้แบบธรรมชาติ (Natural Conversation)
**การแก้ไข:**
1.  **Frontend:** สั่งให้ส่งประวัติการคุย 10 ข้อความล่าสุดไปหาหลังบ้านด้วย
2.  **Backend:** อัปเกรด `smart_query_optimizer` ให้เอาประวัติเดิมมาช่วยตีความคำถาม (เช่น ถามว่า "แล้วโทษคืออะไร?" -> ระบบจะรู้ว่าหมายถึง "โทษของคดีลักทรัพย์" ที่คุยกันก่อนหน้า)
3.  **Synthesis:** บอกให้ LLM ดูประวัติการคุยก่อนตอบ จะได้ไม่พูดซ้ำ
**ผลลัพธ์:** ตอนนี้คุยรู้เรื่องต่อเนื่องแล้วครับ! ถามเจาะลึก ถามต่อ สั่งขยายความได้สบายเลยครับ! 🗣️

### 🎭 ปรับจูนน้ำเสียง (Tone Tuning - Round 2)
**คำสั่ง:** หลังจากแก้แล้ว นายท่านยังรู้สึกว่า "ยังไม่ Dynamic พอ"
**การแก้ไข:** ครั้งนี้ผมงัดไม้ตาย **"Dual-Example Strategy"** ครับ
- ใส่ตัวอย่างให้เห็นชัดๆ 2 แบบใน Prompt เลย
- **Option A (Search):** โชว์ Format ทางการเต็มยศ (### Header)
- **Option B (Chat):** โชว์ตัวอย่างการคุยเล่นแบบ "ห้ามใช้ Header เด็ดขาด"
**ผลลัพธ์:** การมีตัวอย่างให้ดู (Few-Shot Prompting) จะช่วยให้ AI เข้าใจบริบทการสลับโหมดได้ดีกว่าคำสั่ง text ธรรมดาครับ 🚀

### 🎭 ปรับจูนน้ำเสียง (Tone Tuning - Round 3: Strict Mode)
**คำสั่ง:** นายท่านยังเจอว่า AI ติดนิสัยชอบทำสรุปยาวๆ เวลาถามเจาะจง
**การแก้ไข:** ครั้งนี้ผมใช้ไม้แข็ง **"Negative Constraints" (ข้อห้ามเด็ดขาด)**
1.  **Restrict Mode A:** สั่งให้ทำสรุปเฉพาะตอน user สั่ง "สรุป", "รายชื่อคดี", "เปรียบเทียบ" เท่านั้น
2.  **Default Mode B:** ถ้าถามคำถามเจาะจง ให้เข้าโหมดคุยทันที
3.  **Strict Rules:** ใส่คำสั่ง **"NO HEADERS", "NO TABLES"** แบบตัวใหญ่ๆ ให้ AI เห็นชัดๆ ว่าห้ามทำหน้าตาเป็นทางการ
**ผลลัพธ์:** คราวนี้ AI น่าจะ "คุยเป็นคน" มากขึ้น ไม่ทำตัวเป็นหุ่นยนต์สรุปรายงานแล้วครับ! 🤖 -> 🧑‍💼

## 🧹 ยุทธการ "บ้านสะอาด" (The Grand Refactoring)
นายท่านสั่งให้จัดบ้าน ผมเลยกวาดทุกอย่างให้เรียบกริบ:
- **`src/`**: โค้ดหัวใจหลัก (Backend API + Frontend Web) อยู่ที่นี่
- **`pipelines/`**: สคริปต์ OCR, Cleaning, Upload ถูกแยกไปเก็บในนี้
- **`data/`**: ข้อมูลดิบและ Processed ถูกแยกออกมาต่างหาก
- **`archive/`**: ของเก่า (Phase 2-6) เก็บเข้ากรุเรียบร้อย

ตอนนี้หน้าบ้าน (Root Directory) โล่งสะอาดตา น่านั่งทำงานต่อมากครับ! ✨

### 1. 🛡️ ยกโล่ป้องกันเงินรั่ว (Cloud Run Scalability)

## 🆚 เทียบชัดๆ: แบบเก่า (VPS) vs แบบใหม่ (Serverless)
นายท่านสงสัยว่า "มันต่างจากเมื่อก่อนยังไง?"
ผมเลยเปรียบเทียบให้เห็นภาพชัดๆ ครับ:
*   **แบบเก่า (VPS):** เหมือน **"เช่าบ้านรายเดือน"** จ่ายค่าเช่าทุกเดือน ผีดุ (ไม่มีคนอยู่) ก็ต้องจ่าย หลังคารั่วต้องซ่อมเอง
*   **แบบใหม่ (Serverless):** เหมือน **"นอนโรงแรม"** จ่ายเฉพาะคืนที่นอน มีแม่บ้านทำความสะอาดให้ แอร์เสียย้ายห้องให้ทันที
